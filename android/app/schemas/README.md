# Room Schema Exports

These JSON files are auto-generated by Room's annotation processor (`room.schemaLocation` kapt
argument in `build.gradle.kts`). They document the exact SQLite DDL at each database version and
must be committed so that schema changes are visible in code review.

## Regenerating after a schema change

```bash
cd android
./gradlew :app:kaptDebugKotlin
```

Room writes one JSON per version to this directory. Commit the updated file alongside the entity
or migration change so reviewers can diff the before/after schema in one PR.

## Why the `identityHash` values say `REGENERATE_VIA_KAPT`

The identity hash is an MD5 computed by the Room annotation processor from the canonical CREATE
TABLE statements. It cannot be hand-computed reliably, so the placeholder files here record the
correct table structure for human reference but carry a sentinel hash. Running the kapt task above
overwrites each file with the real hash. The migration test (`CandleMigration1To2Test`) does **not**
depend on these hashes — it validates migration behaviour by constructing the v1 database from raw
SQL instead of using `MigrationTestHelper.createDatabase()`.

## Running the migration test

```bash
# Connect a device or start an emulator, then:
cd android
./gradlew :app:connectedDebugAndroidTest \
  --tests "com.novacycle.data.local.CandleMigration1To2Test"
```

The test:
1. Constructs a v1-shaped SQLite database (no `timeframe` column, PK = ticker + timestamp)
2. Inserts two synthetic daily candle rows
3. Opens it with `Room.databaseBuilder` supplying `MIGRATION_1_2` and `MIGRATION_2_3`
4. Asserts both rows survive with `timeframe = 'daily'`

If `MIGRATION_1_2` ever drifts from the `CandleEntity` definition Room will throw
`IllegalStateException: Migration didn't properly handle ...` — the test catches this without
needing the identity hash from the JSON files.
